# 3D assembly solver

The scheduler accepts `se3` and `multivariate` requests with an `inputs.assembly` of the frozen Schema 11 `AssemblyModelV1` type. Existing 1D requests continue to use the integer q domain engine. Each solved part returns a row-major 4×4 `nominalTransform` with the translation in the last column, suitable for `Matrix4.set(...nominalTransform.flat())`.

- The solver fixes the first part by default. Use `fixedPartIds` to choose a datum or `[]` to expose rigid-body modes. `remainingDofs` contains coupled world-coordinate translation and rotation modes. `redundantMateIds` identifies constraints that add fewer independent equations than expected in input order. The conflict search returns a locally infeasible subset in each affected movable component. Residuals describe the returned best-fit pose. The numerical solver does not prove global infeasibility.
- `face-contact` aligns opposing planar normals and closes signed normal separation. `parallel` aligns unoriented directions. `coaxial` aligns axis directions and centers transversely. `floating-clearance` takes the hole first and shaft second, with radial travel bounded by `[minQ,maxQ]` and the radius difference. `distance` is signed normal separation if either feature is planar, or Euclidean origin separation otherwise. `3-2-1` uses the six point-to-datum-plane contacts in the frozen structure. The numerical rank comes from the geometry. Stored `constrainedDofs` provides metadata.
- `gap` uses signed normal separation for a planar datum and Euclidean origin distance otherwise. `flush` uses the absolute normal separation of two planar features. `center-distance` uses Euclidean origin separation. `coaxiality` uses the transverse separation of the second axis origin from the first axis. `angle` uses radians and identifies cylinder and cone axes up to sign.
- Simulation inputs describe independent, zero-mean normal variations. Translation uses integer q and rotation uses radians about the feature origin in the world-aligned tangent frame. The nominal equality mates transfer small feature variations to dependent part poses through a linearized least-squares solve. Sampling then evaluates the nonlinear 3D measurement formulas. This model omits contact switching and does not enforce floating-clearance intervals again for each draw.
- `extremeEstimate` evaluates the declared tolerance endpoints and nominal axis probes. It is a deterministic estimate without guaranteed bounds. `threeSigma` comes from the sampled mean and standard deviation. Cp/Cpk use the supplied specification limits when sigma is positive. PPM is the empirical fraction outside those limits, with resolution of 20 PPM at 50,000 draws. Contributions use linear and quadratic first-order main effects. Nonlinear interactions and estimation noise can leave their fractions short of or above 100% in aggregate.
- Incremental requests use the current `baselineRevision` and the same parameter ID, DOF and feature binding. The worker reuses every standardized draw, nominal poses and transfer coefficients. It evaluates the same sample count and updates every dependent measurement and its diagnostics. Other measurements use their cached result. A worker restart discards the baseline.

The mate draft API consumes extracted coplanar and coaxial candidate pairs. The saved-project callers recover candidates from persisted, q-quantized topology if a live report is unavailable. Drafts carry stable feature evidence, including the verified attachment ID, SHA-256 and solid index for saved STEP projects. The frozen five-way `EvidenceRef` union has no STEP branch. The draft carries topology references in `topologyEvidenceRefs` and retains validated, explicitly supplied `EvidenceRef` entries in `evidenceRefs`. Coplanarity describes the supporting planes and gives no finite-area contact guarantee.

Run the worker regression suite with `node --import ./mcp/register-ts.mjs --test src/core/solver/test/solver.node.test.mjs`. Run the six-trial benchmark with `node src/core/solver/test/benchmark.mjs`. The benchmark times the scheduler round trip for the first cold call and five warm calls on the same four parts, five mates, nine parameters, five measurements and 50,000 samples. Each trial changes a single angular tolerance, recomputes three dependent measurements, and reuses two cached results. The benchmark accepts an optional path to the packaged solver worker.

## GD&T simulation

For assemblies with controls, `multivariate` returns `gdt.baseline` with the frozen `GdtStackupMetrics` shape. Pass `gdtEdits: [{ gdtId, toleranceQ, modifier }]` on the initial request or `incremental: { baselineRevision, edits }` on the resident worker to obtain `gdt.whatIf` and `gdt.recalculatedGdtIds`. Each accepted incremental edit advances the revision and becomes the comparison point for the next edit. The worker reuses the original physical process samples and scores the revised acceptance zone, so a drawing change has no effect on the modeled manufacturing process. A new full run is needed to model a new process.

- The ordered datum reference frame (DRF) uses independent simulator constraints in precedence order. A partial frame receives `DRF_UNDERCONSTRAINED` and uses a deterministic orthogonal completion for its free coordinates. Redundant or incompatible references that add no independent constraints receive `DRF_DEGENERATE`; the affected control has no statistical contribution. An archive flatness control is evaluated locally without any stored datum references. Material modifiers on non-size features resolve to RFS with `ILLEGAL_MODIFIER`.
- Schema 11 stores a cylinder origin, direction and radius. When finite engagement or the material side is known, pass `gdtFeatureGeometry: { [featureId]: { spanQ, external } }`. Cylinders default to holes. Parametric parts use the matched blind-hole depth or approximate span from body dimensions. Imported features without span metadata use a 1 mm reference span. Cylindrical spans are centered at the stored origin for end checks. Position uses the modeled feature location as its basic location. These are small-displacement simulator models with symmetric engagement and sampled clearance, with no contact search or virtual boundary adjustment from a datum's own control.
- Samples from mulberry32 use uniform disks for radial error, independent uniform components for two-direction position bands, and uniform size deviations within the declared material limits. The per-control SDT is combined with the assembly's linearized relative feature motion from the existing independent normal parameters. The shared datum motion is keyed by controlled part and ordered datum IDs and resolved modifiers. It uses half the available diameter clearance and one translation/rotation per frame per trial. Angular controls use projected end difference. Flatness represents local tilt and form within one peak-to-valley budget. Coaxiality checks both ends of the full axial span. The GD&T conformity statistics and the nominal 3D measurement statistics are separate result fields.
- GD&T PPM is the sample fraction failing at least one valid control (20 PPM per trial at 50,000 samples). Cpk is the minimum one-sided margin index across controls, computed as mean of `T_eff - error` divided by three sample standard deviations of that margin. A zero margin standard deviation yields null. The reported 3σ interval is mean error ± three sample standard deviations for the governing control, in mm. If all indices are null, the first valid control supplies the interval. With no valid controls, the frozen metric fields carry null Cpk, zero PPM and `[0, 0]` alongside warnings and an empty contributions list.
- Variance shares are each control's marginal error variance divided by the sum of marginal variances. They do not allocate cross-feature covariance. Datum shift percentage uses paired draws and is the sum of squared changes caused by datum motion divided by that sum plus the centered sum of squares of the shifted error. Mean bonus is sampled additional zone width in mm.

Run the analytical and worker tests with `node --import ./mcp/register-ts.mjs --test src/core/solver/test/gdt.node.test.mjs`. Run `node src/core/solver/test/gdtBenchmark.mjs` for six full round trips at 50,000 samples and 144 edits covering every control and all three modifiers. Its performance gates apply to this fixture.
