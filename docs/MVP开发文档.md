# 轴系轴向公差链分析与修改追踪工具：MVP 开发文档

版本：1.0  
编写日期：2026-11-04  
用途：单人借助 AI 开发的实施依据与验收基线。

## 1. 产品目标与竞争依据

帮助独立机械设计师建立一维轴向尺寸链，判断关键轴向间隙的极限范围，并在尺寸修改后立即看到结果变化及对应尺寸。

核心任务：用户输入并确认一条尺寸链后，完成“建链—计算—判断—修改比较—保存分析记录”。

专用工具的价值来自可编辑的工程模型、确定性的计算、明确的来源和可复用的修改记录。解释文字由 AI 生成并不构成核心优势。MVP 即使关闭 AI，也必须完成全部核心任务。

待验证的产品假设：相较于用户用聊天工具整理尺寸并反复重新计算，专用工具在连续修改中能减少操作和转录错误，使结论更容易复核。这是验证目标，尚不是已证明的市场结论。

## 2. 首版用户与典型任务

目标用户：能理解尺寸偏差与基本尺寸链、需要核算小型轴系装配间隙的机械设计师或机械专业学生。

典型任务：轴向容纳长度 H 内安装轴承 B1、隔套 S、轴承 B2，分析剩余间隙：

`C = H - B1 - S - B2`

该案例只是用于验证尺寸关系的简化模型，不代表任意实际轴承装配结构均适用。用户需要确认真实装配中的接触面、定位关系和作用方向。

首版支持多个项目，每个项目仅有一条尺寸链、一个封闭环。尺寸链包含 2—20 个组成环，各环系数只能为 +1 或 -1，同一环不可重复使用。

## 3. MVP 范围与非目标

### 必须实现

1. 创建、重命名、复制和删除本地项目。
2. 编辑组成环：代号、名称、基本尺寸、上下偏差、方向、来源备注。
3. 显示尺寸链表达式、尺寸表和一维贡献示意图。
4. 极值法计算封闭环基本尺寸、上下极限尺寸、上下偏差与公差。
5. 设置封闭环允许区间，判断极限范围是否完全落在区间内。
6. 显示下限裕量、上限裕量及各组成环的公差贡献。
7. 保存基线、编辑工作方案、比较变化、恢复基线。
8. 本地自动保存、项目 JSON 导入导出、浏览器打印分析报告。
9. 内置可复现演示案例和核心计算自动化测试。

### 后续版本

- 从 PDF 或 CAD 自动读取尺寸、几何拓扑与尺寸链。
- RSS、蒙特卡洛及其他统计分析。
- 标准公差等级、配合和轴承厂商数据查询。
- 自动优化公差、成本估算、热变形或受力变形分析。
- CAD 插件、三维展示、云端协同和多封闭环网络。
- AI 自然语言建链和智能解释。

首版使用用户明确输入的数值偏差，不根据 H7、h6 等符号推断数值，不声称符合某项未实现和未验证的标准。

## 4. 专业模型与计算规则

### 4.1 基本定义

统一使用 mm。组成环 i 的基本尺寸为 Nᵢ，下偏差为 EIᵢ，上偏差为 ESᵢ，系数 sᵢ∈{+1,-1}。

输入约束：Nᵢ > 0，EIᵢ ≤ ESᵢ，且 Nᵢ + EIᵢ ≥ 0。允许上下偏差均为正或均为负，不能强制要求 EI ≤ 0 ≤ ES。

- 下极限尺寸：Lᵢ = Nᵢ + EIᵢ
- 上极限尺寸：Uᵢ = Nᵢ + ESᵢ
- 组成环公差：Tᵢ = ESᵢ - EIᵢ
- 封闭环基本尺寸：C₀ = Σ(sᵢNᵢ)
- 封闭环最小值：Cmin = Σ(sᵢ=+1 时 Lᵢ；sᵢ=-1 时 -Uᵢ)
- 封闭环最大值：Cmax = Σ(sᵢ=+1 时 Uᵢ；sᵢ=-1 时 -Lᵢ)
- 封闭环下偏差：EIc = Cmin - C₀
- 封闭环上偏差：ESc = Cmax - C₀
- 封闭环公差：Tc = Cmax - Cmin = ΣTᵢ

必须按照组成环的作用方向选择极限值，不能直接把所有上偏差相加。

该模型计算的是用户定义的线性关系在输入边界下的极限范围。它不自动验证尺寸链是否反映真实装配，也不预测合格率。

### 4.2 目标区间与判定

用户输入允许区间 [Rmin, Rmax]，要求 Rmin ≤ Rmax。输入单位为 mm。

- 满足：Cmin ≥ Rmin 且 Cmax ≤ Rmax，边界相等算满足。
- 不满足：不符合上述条件；允许范围只部分重叠也算不满足。
- 未设置目标：显示结果，但不显示满足或不满足。
- 输入无效：不产生当前结果，标注错误，不保留看起来有效的旧结论。

裕量：

- 下限裕量 Mlow = Cmin - Rmin。
- 上限裕量 Mhigh = Rmax - Cmax。
- 负裕量代表该侧超出目标区间。

封闭环允许为负值，用来表达用户约定下的负间隙。报告必须说明其物理意义由用户定义。

### 4.3 公差贡献与修改影响

公差贡献比例 pᵢ = Tᵢ / ΣTᵢ。ΣTᵢ=0 时显示“所有输入公差为零”，比例显示为“—”。

比例用于说明各项对极限区间宽度的贡献，不能解释成失效概率、缺陷原因或成本最优建议。

基本尺寸局部变化关系：ΔC₀ = sᵢΔNᵢ。修改偏差后必须完整重算 Cmin、Cmax；不把公差收紧等同于必然满足目标。

首版提供贡献排序和变化对比，不自动决定哪个零件应该收紧公差。

### 4.4 数值精度

输入最多 4 位小数，最小步长为 0.0001 mm。将十进制字符串精确转换为整数单位 q，1 q = 0.0001 mm。所有求和、比较和存储使用安全整数，避免浮点误差影响边界判断。

先校验十进制格式及位数，再拆分整数与小数部分转换；不要使用 parseFloat(value) × 10000 作为唯一转换方式。超过精度的输入提示用户修改，不静默截断。

单字段绝对值上限 1,000,000 mm，并对中间结果检查 Number.isSafeInteger。界面默认显示 4 位小数；导出保留整数值及单位。百分比可用浮点数显示，不参与工程判定。

## 5. 页面与交互

### 5.1 项目首页

项目列表显示名称、更新时间、当前计算状态。操作包括新建、打开演示案例、导入 JSON、复制与删除。删除已有项目需确认。

### 5.2 分析工作台

桌面布局：左侧组成环表，中部表达式与示意图，右侧结果卡；底部为方案比较。窄屏改为上下排列。

组成环字段：

| 字段 | 规则 |
|---|---|
| 代号 | 项目内唯一，必填；例如 H、B1、S、B2 |
| 名称 | 必填，例如隔套 |
| 基本尺寸 | 十进制字符串，>0 |
| 下偏差、上偏差 | 显式输入数值，允许 0 |
| 方向 | “增加封闭环”或“减小封闭环”，同时显示 + / - |
| 来源备注 | 可选，例如图纸编号、尺寸位置和版本 |

表格同时显示每项的上下极限尺寸。支持增删、调整顺序；重排不得改变计算结果。无效输入在对应单元格提示原因。

表达式始终可见，例如 `C = +H - B1 - S - B2`。用户需要勾选“已核对尺寸关系与作用方向”，才显示正式的目标判定和允许导出报告；未确认时可以预览计算，并标注“待确认”。任何组成环增删、代号、方向或数值改变，均清除确认状态。

一维贡献示意图使用 SVG：正项向右、负项向左，每段标注代号与基本尺寸，选择段时突出对应表格行。图标题明确写“尺寸链关系示意，非装配图”。为保证可读性可以非等比例绘制，但必须标注“非比例”。不得暗示系统已经识别真实装配拓扑。

结果卡显示：C₀、Cmin、Cmax、EIc、ESc、Tc、允许区间、状态、两侧裕量。图形区用共用坐标轴显示结果区间与允许区间；零宽区间使用标记点，不能消失。

### 5.3 基线与工作方案

用户点击“保存为基线”后创建不可变快照；后续修改保留在工作方案中。对比表列出变化字段、变化前后值，以及 Cmin、Cmax、Tc、裕量和判定的变化。

MVP 只保留一个基线及当前工作方案，不建设复杂版本系统。重新覆盖基线、恢复基线均需确认。修改后先取消关系确认，用户复核后再给出正式判定。

### 5.4 报告

使用独立打印视图及浏览器“打印/另存为 PDF”，无需服务端 PDF 引擎。报告包含：

1. 项目名称、报告时间、项目 ID、计算引擎版本。
2. 分析方法、mm 单位、适用范围与用户关系确认状态。
3. 完整输入表和来源备注。
4. 尺寸链表达式、公式与代入结果。
5. 目标区间、计算区间、两侧裕量与判定。
6. 公差贡献表及基线对比（如有）。
7. 假设与待确认事项。

打印样式使用 A4、可换行的表格和重复表头，隐藏操作按钮。报告只包含已确认且有效的数据；不允许把 AI 解释作为计算依据。

## 6. 数据结构

建议 TypeScript 类型：

```ts
type Q = number; // 经校验的安全整数，单位 0.0001 mm

interface DimensionTerm {
  id: string;
  symbol: string;
  name: string;
  nominalQ: Q;
  lowerDeviationQ: Q;
  upperDeviationQ: Q;
  sign: 1 | -1;
  sourceNote: string;
}

interface ChainDefinition {
  terms: DimensionTerm[];
  target: { minQ: Q; maxQ: Q } | null;
  assumptions: string;
  relationConfirmed: boolean;
}

interface Project {
  schemaVersion: 1;
  engineVersion: string;
  id: string;
  name: string;
  createdAt: string; // ISO 8601
  updatedAt: string;
  working: ChainDefinition;
  baseline: {
    savedAt: string;
    definition: ChainDefinition;
  } | null;
}

interface ChainResult {
  nominalQ: Q;
  minQ: Q;
  maxQ: Q;
  lowerDeviationQ: Q;
  upperDeviationQ: Q;
  toleranceQ: Q;
  status: 'within' | 'outside' | 'no-target';
  lowerMarginQ: Q | null;
  upperMarginQ: Q | null;
  contributions: { termId: string; toleranceQ: Q }[];
}
```

计算结果从定义实时派生，不作为导入文件中的可信事实。导入项目、打开基线、恢复缓存后均重新校验和计算。界面输入草稿保持为字符串，合法后再转换为领域数据；禁止用 0 代替临时空白。

## 7. 技术方案与模块边界

推荐：React + TypeScript + Vite；SVG 绘图；Zod 校验；Vitest 测试；IndexedDB 保存项目。使用成熟轻量组件库或普通 CSS，优先完成主流程。

不需要后端、账号、云数据库或模型 API 密钥。项目资料留在本地，提供 JSON 备份；存储失败时明确提示用户导出，不能显示“已保存”。

建议目录：

```text
src/
  domain/units.ts             十进制字符串与整数单位转换
  domain/validation.ts        业务数据校验
  domain/calculate.ts         纯函数极值计算
  domain/compare.ts           基线差异
  domain/types.ts
  storage/projects.ts        IndexedDB 与导入导出
  components/DimensionTable.tsx
  components/ChainDiagram.tsx
  components/ResultPanel.tsx
  components/ScenarioCompare.tsx
  pages/ProjectList.tsx
  pages/Workspace.tsx
  pages/PrintReport.tsx
  fixtures/demo.ts
```

计算模块不得依赖 UI、存储或 AI。所有计算只有一个入口，工作台、对比与打印调用同一实现。核心函数：

```ts
parseMm(input: string): Q
formatMm(value: Q): string
validateChain(input: unknown): ValidationResult
calculateChain(chain: ChainDefinition): ChainResult
compareDefinitions(baseline: ChainDefinition, working: ChainDefinition): Diff
```

JSON 导入只接受 schemaVersion=1，大小上限 1 MB，组成环最多 20 项；校验未知版本、重复 ID/代号、非法整数、越界和日期格式。拒绝损坏数据并保留现有项目。导入 ID 冲突时生成新 ID，不覆盖已有项目。文本渲染不用原始 HTML。

自动保存防抖约 500 ms，显示保存中、已保存、保存失败；输入无效的草稿另行缓存，不能污染上一个有效领域模型。刷新恢复时应保留草稿并显示待修正状态。

## 8. 标准验收案例

所有数值单位为 mm。以下结果为本项目公式直接计算的测试基线，不引用外部标准。

### 案例 A：不满足目标的轴向间隙

| 代号 | 方向 | 基本尺寸 | 下偏差 | 上偏差 |
|---|---:|---:|---:|---:|
| H | +1 | 100.0000 | 0.0000 | 0.1000 |
| B1 | -1 | 20.0000 | -0.0200 | 0.0000 |
| S | -1 | 59.8000 | -0.0500 | 0.0500 |
| B2 | -1 | 20.0000 | -0.0200 | 0.0000 |

目标区间：[0.1000, 0.3000]。

- C₀ = 0.2000。
- Cmin = 100.0000 - 20.0000 - 59.8500 - 20.0000 = 0.1500。
- Cmax = 100.1000 - 19.9800 - 59.7500 - 19.9800 = 0.3900。
- EIc = -0.0500，ESc = +0.1900，Tc = 0.2400。
- 下限裕量 +0.0500，上限裕量 -0.0900；判定“不满足”。
- H 与 S 的公差贡献各为 0.1000，B1 与 B2 各为 0.0200。

### 案例 B：修改后的满足方案

从 A 修改 H 上偏差为 +0.0300，S 下偏差为 -0.0200、上偏差为 +0.0200，其他不变。

- C₀ = 0.2000，Cmin = 0.1800，Cmax = 0.2900。
- EIc = -0.0200，ESc = +0.0900，Tc = 0.1100。
- 下限裕量 +0.0800，上限裕量 +0.0100；确认关系后判定“满足”。
- 对比 A：Cmin 增加 0.0300，Cmax 减少 0.1000，Tc 减少 0.1300。

这是数值方案对比，不构成制造可行性或加工成本建议。

### 案例 C：负间隙和边界

P：+1，10.0000，下偏差 -0.1000，上偏差 0。Q：-1，10.0500，下偏差 0，上偏差 +0.0500。

结果：C₀=-0.0500，Cmin=-0.2000，Cmax=-0.0500，Tc=0.1500。目标 [-0.2000,-0.0500] 时判定满足，验证负数和边界相等。

### 必测异常和性质

- 上偏差小于下偏差、尺寸为空、非数字、超 4 位小数、重复代号、目标下限大于上限：阻止当前判定。
- 全零公差：Cmin=Cmax，贡献比例不出现 NaN。
- EI 和 ES 均为正或均为负：合法并正确计算。
- 组成环重排：结果完全一致。
- 对任意合法输入：Cmax≥Cmin，Tc=ΣTᵢ，ESc-EIc=Tc。
- 正项基本尺寸增加 δ：C₀、Cmin、Cmax 均增加 δ；负项则均减少 δ。
- JSON 导出再导入：工程输入及重算结果一致。
- 编辑后刷新：恢复工作方案与草稿；基线不被自动覆盖。

## 9. 开发顺序与完成门槛

### 阶段一：计算内核

实现类型、整数单位、校验、计算函数和案例 A/B/C 测试。门槛：测试全部通过，任何界面开发都不得另写一份公式。

### 阶段二：可用工作台

完成表格、表达式、示意图、结果卡、目标区间和确认流程。门槛：从空项目手动建立 A，再修改到 B，不借助代码操作。

### 阶段三：持续修改与保存

完成基线、比较、IndexedDB、自动保存、导入导出。门槛：刷新不丢失有效输入，导入不覆盖旧项目，基线可恢复。

### 阶段四：报告与演示

完成打印布局、内置示例、错误状态和移动端基本可用性。门槛：导出的分析报告可复核全部输入、公式与结果，A4 打印无截断。

首版完成定义：上述必须功能可用；核心测试通过；三个案例人工复核；开发者控制台无未处理错误；无网络时本地分析仍可用；不出现没有依据的工程结论。

## 10. 如何验证用户为什么选择它

找 3—5 名理解尺寸链的目标用户，用相同输入分别完成：建立案例 A、连续三次修改、判断结果、留下可复核记录。允许用户在对照组使用自己习惯的聊天模型和表格工具，不刻意限制能力。

记录完成时间、人工转录次数、最终数值错误、能否定位输入来源、能否恢复之前的方案。对同类任务交叉安排使用顺序，减少熟练度影响。

MVP 的继续投入门槛建议：至少 3 位用户能独立完成主流程；没有核心计算错误；多数参与者在连续修改时操作更少，并明确愿意在下一次相似任务中再次使用。样本很小，只用于迭代，不能宣称普遍效率提升。

## 11. 可直接交给 AI 开发的首轮任务

请严格按照本开发文档实现阶段一，不增加后端、模型调用、自动读图或统计法。使用 TypeScript 建立整数单位转换、领域类型、输入校验、极值法计算和基线比较；用 Vitest 覆盖案例 A/B/C 及异常与性质测试。计算函数与 UI 完全分离。完成后给出测试结果、实际文件位置以及仍未实现的阶段。不要把 AI 输出用于数值判定，也不要擅自改变公式、输入精度或验收结果。

阶段一通过后，再逐阶段实现工作台、存储、比较与打印，每个阶段沿用同一计算内核，并按对应门槛验收。
