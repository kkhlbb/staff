# L1–L5 解决顺序

写于 2026-11-12。基线 `main = 5b2f06c`。
依据的事实（代码实测）：`MAX_EXTRACTION_PAGES = 100`（`src/document-extraction/types.ts:33`），r4 是 170 页 → **整份 0 候选**；
三维是 `BufferGeometry` 网格（`src/parts/shaftDemoGeometry.ts:132`）；DXF 已支持 r12/2000，**无 DIMENSION 实体**（`src/dxfExport.ts:16`）。

---

## 排序原则（先说清，再看表）

1. **先修"有/没有"，再修"多少"。** 整份失败（页面超限）比抽得少严重一个量级。
2. **入口提上来的收益，必须有地方接住。** OCR 一旦上线，候选数会涨；确认环节不先做，涨多少就被吃掉多少。
3. **便宜的"专业度"先做，贵的"能力"后做。** 统计公差是一天量级，GD&T 是重做数据模型。

---

## 阶段 0（不是代码，但不做就没法验收）

- 没有真实样本，L1/L2 的验收全是自说自话（现在 43.5% 的语料是论文和标准）
- 没有工时基线，"省 70% 时间"就是空话；L2 做完也没有对照

**这一步只能你出。** 拿到之后我先只跑提取，不建项目。

## 增补（2026-11-12）：意图驱动建件 = L1-c，位置提前

用户提出「希望 agent 从意图开始辅助建项」，实测代码后确认**这不是加个入口，是要动数据模型底部**：

| 缺什么 | 代码证据 |
|---|---|
| 来源身份写死 PDF | `ExtractionSourceIdentity = {documentId, revisionId, sha256, blobKey, pageCount}`（`types.ts:88-94`）；`planApplication` 第一件事就是校 revisionId + sha256（`draft.ts:581-589`） |
| 没有"从零建"工具 | `toolSchemas.ts` 只有 6 个：context / confirmed / apply / stage / preview / export |
| `apply` 无米下锅 | 要求 `mapping.formulaId` 取 `kind="formula"` 候选的 candidateId |
| `stage` 前提 | 「在**现有**工程草稿上修改一个参数」，只接受 inner/outer/length |
| 没有写环、写条款、写绑定的工具 | 六个工具里一个都没有 |

**三条实现路径，只推荐 A：**

- **A（推荐）** 新增来源类型 `user-intent`，把 `planApplication` 的来源校验泛化 → 复用同一套门禁与校验，改动集中在一处
- B 平行一套 `IntentDraft` 类型 → 校验要重写一遍，等于两套真相，**不许**
- C 走手动路径、agent 只填参数 → 没证据链、绕开门禁，**破"不虚构"原则，不许**

**必须同时定的语义**：无来源项目的状态怎么标（建议固定「无外部来源 · 全部用户输入」）、能不能出图、能不能导出。**不许让它看起来和有任务书的项目一样有证据。**

**位置**：排在 **1（整份失败）之后、2（确认效率）之前**。理由：这决定"这个产品是不是 agent"，是定位问题不是功能问题；但成本是**中**（改来源抽象 + 3~4 个新工具），必须先定状态语义再动手。

## 为什么是这个顺序

**1 必须在最前**：r4 是**整份 0 候选**。这不是"抽得少"，是"这份文档对我们等于不存在"。改成 100 页 + 100 页，成本一天，收益是"一份 170 页的文档从不可用变成可用"。

**2 排在 3 前面**：OCR 上线必然让候选数变多，而现在的瓶颈已经不是"能不能抽出来"，而是"74 条阻塞要人一条条看"。**先做确认效率，OCR 的收益才留得住。**

**3（OCR）是决定性的一战**：真实任务书大量是扫描件。这一条不做，前面全是修边角。但它成本最高，而且**必须先有 2 才敢做**。

**4（统计公差）紧跟其后**：它是**一天量级**的事，纯计算，直接补上"只会极值法"这个最刺眼的短板——对标 DCC 的三种算法。便宜、显眼、风险低，没有理由往后拖。

**5（L4 死图）**：真正的问题不是"DXF 不关联"，而是"图是快照"。解法是**保证任何时候都能从项目版本重出同一张图**（字节一致），而不是追求 CAD 关联性（DXF 格式本身就不支持）。顺手把 2000 版升级成真 `DIMENSION`。

**6（STEP）**：只做**回转体**这一条路，解析式生成，不引 OCCT/FreeCAD。做得了就交得出三维，做不了就明写"只能二维"。**不承诺通用体。**

**7（GD&T）最后，且我建议先不做**：它要求重做数据模型（从"一维链 + 一个区间"扩到基准体系 + 形位公差框格），等于换一个产品。**在真实任务书样本到位、确认效率被验证之前做这个，是在没有地基的地方盖二楼。**

---

## 我的建议：先做 1、2、4、5 四件

这四件加起来是**小到中成本**，但能把产品从"演示能跑"推到"能在一份真实文档上用一次"：

```
1  整份失败 → 部分成功        （L1-a）
2  74 条阻塞能批量处理        （L2）
4  RSS + 蒙特卡洛             （L3-a）
5  图能重出 + 2000 版真尺寸    （L4）
```

**3（OCR）和 6（STEP）是"大"，要等你拿到真实样本、确认 OCCT 那条路可行之后再上。**
