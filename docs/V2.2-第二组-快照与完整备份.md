# V2.2 第二组：不可变分析快照与完整备份

日期：2026-11-08  
分支：`agent/dsh-v2.2`（在第一组提交 `37ba241` 上追加）  
范围：C 不可变分析快照与报告；D 完整 `.cunlian.zip` 备份与恢复。

## 1. 本次行为变更（必须明确告知）

旧行为（V2.1 及以前）：

- 打印报告读取工作台实时项目、草稿与来源状态；
- 只有“输入有效且关系已确认”才允许进入报告；
- 报告时间取打开报告的时刻，工作数据变化会影响下一次打开。

新行为（本组起）：

1. **报告只由不可变 `AnalysisSnapshot` 生成**。打开报告只按 `snapshotId` 读取快照，不再读取项目、草稿、来源或计算结果的实时数据。
2. 工作台入口从“打印报告”改为“创建分析快照”。输入通过校验即可创建；**审查未完成也允许创建**，但创建前会二次确认，报告中会明确标注“审查未完成（N 项待办）”，并列出全部待办，不能被标为“已完成复核报告”。
3. 报告门槛从“有效 + 已确认”改为“快照存在”。关系是否确认、来源是否核对属于快照内冻结的审查状态，单独显示，不再阻止报告生成。
4. 旧链接 `#/project/<id>/report` 不再读取实时数据，会转到分析快照列表并显示行为变更说明；新报告链接为
   `#/projects/<id>/reports/<snapshotId>`。
5. 工作数据变化后，旧快照在列表中派生为“历史”，但**不重算、不覆盖**其输入、结果、来源清单与规则结果。

该变更已同步写入提交说明与本文档，没有静默改变产品行为。

## 2. C：不可变分析快照

### 2.1 数据与存储

- 数据库版本 `7`，新增 `snapshots` store（`keyPath=id`，索引 `projectId`、`createdAt`）。
  版本升级只补缺失 store/index，不重建、不清空。
- 快照记录（`src/history/snapshots.ts`，`AnalysisSnapshot`）冻结：
  - 项目 ID / 名称、创建时间、引擎版本、审查规则版本；
  - 完整链定义 `definition`、当前草稿 `draft`、计算结果 `result`；
  - 统一审查结果 `review`（findings、pending、byStatus 等）；
  - 来源清单 `sourceManifest`：每个绑定的版本 ID、文件名、SHA-256、页、PDF 区域、
    页面边界、附件可用性、三项来源规则状态、历史来源理由；
  - 基线 `baseline`、审查状态 `status`（complete/pending）与待办数；
  - 输入指纹 `inputFingerprint`。
- 不可变实现：
  - 写入使用 `IDBObjectStore.add()`，重复 ID 直接失败；写入前显式查询并返回
    `snapshot_exists`，不提供更新函数；
  - 内存对象递归 `Object.freeze`，嵌套数组/对象不可原地修改；
  - 快照与 `analysis_snapshot_created` 事件在同一事务写入。
- 历史标记：
  - 列表比较快照的输入指纹与当前项目/草稿/关系凭据/来源元数据；
  - 只有“与当前内容一致且最新”的快照显示“当前”，其余显示“历史”；
  - 只比较指纹，不重新计算快照结果。

### 2.2 共用审查逻辑

快照创建调用 `src/review/rules.ts` 的 `evaluateReviewChecklist`，与工作台审查侧栏是同一函数；
报告渲染的是快照中冻结的该结果。`PrintReport` 没有第二套“已确认/未确认”判定，也没有
`calculateChain` 之外的公式实现。

### 2.3 报告与页面

- `src/pages/PrintReport.tsx`：按 `snapshotId` 读取快照，显示项目/快照 ID、创建时间、
  引擎与规则版本、审查状态、计算状态、完整输入、公式、结果、贡献、来源清单、
  审查待办、基线对比与边界说明。
- `src/pages/SnapshotList.tsx`：快照列表（创建时间、冻结审查状态、计算状态、版本、
  当前/历史标记、打开报告）。
- `src/pages/Workspace.tsx`：创建快照入口；审查未完成时二次确认；创建成功后进入该快照报告。
- `src/App.tsx`：新增快照列表与 `reports/<snapshotId>` 路由；旧报告路由转为快照列表。
- `src/workspace/usePersistedWorkspace.ts`：暴露当前 `relationState`，避免快照读取落后于
  界面的项目记录。

## 3. D：完整备份与恢复

### 3.1 ZIP 库与参考来源

- 库：`@zip.js/zip.js`，**精确版本 `2.24.0`**（BSD-3-Clause），写入
  `package.json` 与 `package-lock.json`；只安装在项目内，没有全局依赖。
- 官方文档：<https://gildas-lormeau.github.io/zip.js/>（查阅时间 2026-11-08）
- 源码仓库：<https://github.com/gildas-lormeau/zip.js>（查阅时间 2026-11-08）
- 使用 `ZipReader` / `ZipWriter` + `Uint8ArrayReader` / `Uint8ArrayWriter`，关闭
  Web Worker，保证浏览器与测试环境行为一致。

### 3.2 包结构

```text
manifest.json
projects/<id>.json
drafts/<projectId>.json
sourceDocuments/<id>.json
sourceRevisions/<id>.json
sourceBlobs/<blobKey>.json      # 附件元数据（哈希、大小、作用域）
sourceFiles/<blobKey>.bin       # 附件原始字节
bindings/<id>.json
events/<id>.json
snapshots/<id>.json
importSnapshots/<id>.json
migrationBackups/<id>.json
```

`manifest.json` 包含：

- `format=cunlian-backup`、`formatVersion=1`、创建时间、数据库/项目 schema 版本；
- 各 store 计数、项目摘要；
- 每个文件的 `path / sha256 / byteSize` 与解压总量；
- `excludes.mappingTemplates.included=false`、模板数量及明示：
  **“本备份不包含全局映射模板（mappingTemplates）”**。

### 3.3 导入校验（全部通过才写库）

生成前先拒绝两种会产生“不可恢复包”的情况：空库（`empty_backup`）与仍含未迁移
V1 记录的项目（`legacy_projects`，提示先完成迁移）。

1. ZIP 结构安全（`src/backup/zip.ts`）：
   - 条目数 ≤ **500**；
   - 解压后总量 ≤ **150 MiB**（先按中央目录声明值预检，再按实际解压字节复核）；
   - 拒绝绝对路径、`..`、`.`、反斜杠、盘符、控制字符、尾随点/空格、空路径段；
   - 解码百分号编码后再检查一次，阻止 `%2e%2e` 等变体；
   - 拒绝目录、符号链接、加密条目；NFC + 小写规范化后的重复条目；
   - 单条目实际解压大小必须与声明一致。
2. `manifest.json` 结构与版本、排除项口径。
3. ZIP 实际文件集合与 manifest 条目集合完全一致；逐文件大小与 SHA-256 核对。
4. 业务记录结构（Zod）与引用一致性：
   - 项目/基线尺寸链走现有 `validateChain`；
   - 文档最新版本、版本所属文档、附件哈希/大小、绑定版本/文档/页码、
     草稿/快照/替换前快照所属项目；
   - 已退役来源作用域（`<projectId>::retired::...`）允许保留，不强制挂在现存项目上。
5. 目标数据库必须为空：逐 store 计数，任一非空即拒绝。
6. 单个 IndexedDB 事务写入全部 store；任一步失败整体 abort。

### 3.4 恢复语义

- 保留：项目数值、基线、来源文档/版本、附件字节与哈希、绑定页码与 PDF 坐标、
  草稿、事件、分析快照、替换前快照、迁移备份。
- 清除人工确认（规格 BAK-01）：
  - `project.relationReview = null`；
  - 绑定 `reviewedTermRevision = null`、`reviewedAt = null`、
    `historicalAcceptance = null`；
  - `relationRevision` 保留，确认凭据失效由既有派生规则判断。
- 为每个恢复项目追加一条 `project_restored_from_bundle` 事件，与数据同事务。
- 全局映射模板不进入备份，恢复后计数为 0，需要重新建立/导入。

## 5. 未完成项与边界

- 恢复只支持**空数据库**；不提供覆盖/合并恢复。目标库任一业务 store 非空即整体拒绝。
- 导出前拒绝空库与未迁移 V1 项目，避免生成无法恢复的包；旧版项目需先完成迁移。
- `.cunlian.zip` 不含全局映射模板（manifest 已明示），恢复后需重新建立/导入。
- 备份在内存中生成与校验，受 500 条目 / 150 MiB 限制；不做分卷、加密、增量备份。
- 报告导出到本机后的文件无法被软件召回或改写；快照只能随项目删除，未提供单条快照删除。
- 历史标记按内容指纹派生。极端情况下仅修改名称/备注后又精确改回，可能重新显示为
  “当前”；快照内容本身仍不变、不重算。数值/方向/目标/来源变化都会改变指纹。
- 恢复后快照内冻结的审查结果仍是恢复前的历史状态（例如仍显示“通过”），
  但项目与绑定的人工确认已清除；新报告需重新创建快照。
- 本组未改计算公式、q 精度、导入/迁移规则；未新增后端、模型调用或自动读图。
