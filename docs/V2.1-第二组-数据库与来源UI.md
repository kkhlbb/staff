## 1. 数据库 v5

### 1.1 新增内容（只增补，不重建）

数据库版本 `PROJECT_DB_VERSION = 5`，新增：

| store | keyPath | index |
|---|---|---|
| `bindings` | `id` | `projectId`、`termId`、`revisionId` |
| `events` | `id` | `projectId`、`createdAt` |

升级仍在共享打开器的 `onupgradeneeded` 中逐项检查：store 不存在才创建，
index 不存在才创建；已有 `projects`、`drafts`、`mappingTemplates`、
`importSnapshots`、`sourceDocuments`、`sourceRevisions`、`sourceBlobs`
一律不删除、不清空、不重建。`events` 记录来源导入、绑定新增/解除；事件与
对应业务写入在同一个 IndexedDB 事务内提交，失败一起回滚。

### 1.2 升级路径证据

`src/storage/db.test.ts`（node 环境，fake-indexeddb 可保留真实 Blob 字节）：

- **带数据的 v4 → v5**：先建立真正的 version=4 库并写入项目、草稿、映射模板、
  替换前快照、来源文档/版本/Blob（`%PDF-` 5 字节）。升级前按 v4 读出全部记录
  和 Blob 字节；`openDatabase()` 一次性升级到 v5 后再次读取，逐字段深比较：
  - 项目、草稿、模板、快照、来源文档、来源版本 `toEqual` 前后一致；
  - `blob.arrayBuffer()` 字节数组与升级前完全相同；
  - `bindings` / `events` 为空，keyPath 与 index 列表正确；
  - 升级事件记录为 `oldVersion=4, newVersion=5`，只发生一次。
- **v1 老库直接 → v5**：只有 `projects` / `drafts` 的 version=1 库，一次打开
  即 `oldVersion=1, newVersion=5`；旧项目/草稿逐字段不变；新 store 全部建出
  且为空。
- v3 → v5、v5 重复打开不重复升级也保留原有用例。

### 1.3 VersionError：部署回滚不能只回退前端

**已实测**：库升到 v5 后，指定 `version=4` 的打开请求会得到 `VersionError`。
`openDatabase({ version: 4 })` 会把它映射为明确中文错误（`database_too_new`）：

> 本地数据库版本高于当前页面请求的 v4。请刷新页面加载最新程序；不要删除数据库或降级，回退前端不能打开已升级的库。

因此：

1. 部署回滚**不能只回退前端**：旧前端（含 `8183b87`）打不开已升到 v5 的库。
2. **不能删库降级**来“恢复”旧前端；那会删除项目、草稿、来源记录和 Blob。
3. 正确处置：刷新/更新所有页面到同一版本；旧标签页必须关闭或刷新。若必须恢复
   旧数据，使用升级前的原始备份导入到**新库**，不要对已升级的库做降级写入。
4. 旧前端自身没有版本提示代码，只能看到浏览器原始 `VersionError`；本提交为
   新前端增加了专用提示（`Workspace` 的“页面程序版本过旧”页），并明确禁止删库。

### 1.4 blocked 与 versionchange：实际覆盖范围

- 自动化（`fake-indexeddb`，`src/storage/db.test.ts` 与
  `src/storage/legacyBackup.test.ts`）：用一个没有 `versionchange` 处理器的原始
  连接占住带真实项目/草稿/来源 Blob 的库，升级请求会先得到 `database_blocked`；
  阻塞期间逐 store 比对的记录与 Blob 字节不变；旧连接关闭后，迟到的升级仍完成，
  实现会关闭那条无人接收的连接，随后 `deleteDatabase` 不再被 blocked。
  **这条是全部数据库记录 + Blob 字节的前后对照，不是空库。**
- 真实 Chrome（2026-11-08，新版构建）：先打开一个不带 `versionchange` 处理的
  “旧连接占位页”，再打开应用。实测 Chrome 并不总是立即派发 `blocked`，页面一度
  长时间停在“正在加载项目…”。加入 15 秒兜底后，界面显示可操作提示
  “项目数据库正被其它标签页占用……请关闭或刷新其它标签页后重试”，关闭旧连接后
  点“重试”恢复。截图：`evidence-v21-b3/blocked-visible.png`。
- 因此不能把“blocked 数据完好”写成在任何浏览器都已证明：**自动化已证明数据与
  Blob 不变；“浏览器提示可见”已在新构建上实测；浏览器内的数据前后对照没有单独做
  （由自动化承担），不是独立复核过的结论。**
- `versionchange`：本版连接注册了处理器，但应用使用“每次操作打开、操作后关闭”的
  短连接，只有升级发生时恰好有操作在途，旧页才会收到 `versionchange`。跨版本实测：
  旧 v5 页面在数据库被新页面升到 v6 后没有持续连接可关闭，页面停在旧界面；再次
  读取/刷新时得到 `VersionError`，旧版 UI 显示“页面程序版本过旧”。截图：
  `evidence-v21-b3/cross-version-old-v5-workspace.png`、
  `cross-version-old-too-new.png`。部署时仍必须把全部页面刷新到同一版本。

### 1.5 删除项目

`deleteProject` 在同一个 readwrite 事务中处理 projects / drafts /
importSnapshots / sourceDocuments / sourceRevisions / sourceBlobs /
bindings / events：

- 项目、草稿、替换前快照删除；
- 来源文档、版本、Blob、绑定、事件只把 `projectId` 改为
  `${projectId}::retired::<新 ID>`（退役作用域），**不级联删除 Blob**；
- 绑定矩形、页码、备注与 Blob 字节不变；重建同 ID 项目不会继承旧来源/绑定；
- 测试逐 store 断言前后记录数不变、Blob 字节一致、旧绑定仍可按 id 读回。

## 2. 来源 UI 与框选

- 来源侧栏：文件/版本列表（版本号、页数、SHA-256 前缀、时间、是否最新）、当前
  打开的 revision、页码跳转、上一页/下一页、缩放 100%/200%、旋转
  0/90/180/270。
- 导入入口：选择文件 → 单文件/页数/项目累计限额 → 逐页可解析（`getPage` +
  `getOperatorList`）→ 写入不可变 revision / Blob / 文档指针 / 事件。失败显示
  明确原因，且不改变当前打开的 revision 或已有绑定/最新指针。
- 框选：`getBoundingClientRect()` 比例映射（不用 `offsetX`）→
  `viewport.convertToPdfPoint` 保存 PDF 坐标 → 显示时
  `convertToViewportPoint` 还原；矩形保存规范化两对角点；页面边界保存
  `page.view` 四元组（允许非零原点），不再使用 `[width, height] + [0,0]`。
- 绑定：一个组成环可保存多条；越界/空区域在 UI 和存储层双重拒绝；绑定不复制
  基本尺寸/偏差/方向，不参与 `calculateChain`，不自动提取数值；解除绑定只删
  绑定记录，不删 revision/Blob。
- 没有 PDF 的项目：计算、结果、导出照常；表格每行显示“无来源绑定”，来源栏显示
  “无来源绑定”，不出现“来源审查通过”。
