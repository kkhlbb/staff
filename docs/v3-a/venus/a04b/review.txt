A. 实际需要保留的问题/改进项（不因配置误判而抹除）
A1. 字体使用固定 px，不能跟随用户默认字体设置：
  src/index.css:18 的 font:15px；:136 的 font-size:16px；:141 的 font-size:13px。
  src/pages/DesktopWorkspace.css:23 的 font:13px；:25、:26 的 font-size:14px；:61 的 font-size:20px；:76 的 font-size:28px。
  这是 token/px-length 中有实质依据的字体适配问题。:76 是本轮新增启动页标题；index.css 为既有全局文件，本轮入口新增引入，不能把其历史代码都记为本轮新增回归。字体大小宜用 rem/相对字号。此处不是声称已复现 WCAG 缩放失败：本轮未执行渲染或缩放测试，浏览器整页缩放与用户默认字体设置也不是同一行为。
A2. 新增 dialog backdrop 未使用语义色变量：DesktopWorkspace.css:84 的 rgb(0 0 0 / 40%)。
  其“原始色直接用于规则”事实成立，适合提取 backdrop token；本次按低优先级一致性改进保留，不把它升级成已证实的视觉/无障碍故障。
A3. index.css:123-126、:135、:147-149 的 database-stale-banner 颜色为直接字面量，属于真实的语义 token 覆盖不足，但均为既有全局样式，不是 A-04b 新增 UI 的回归。可以后续清理，不应为本轮顺带重构整个旧样式。

B. 不适用规则 / 配置误判
B1. element/button、element/input：全部不适用。
  工具要求导入 @/components/ui/button、@/components/ui/input，但仓库没有 src/components/ui 或 components/ui。package.json 未声明 shadcn、Tailwind 或对应 UI 组件库；src 搜索 shadcn|tailwind|@/components/ui 无匹配。现有约定就是原生 HTML 控件 + CSS。不能为了消除工具的配置误判安装库或强制替换原生控件。
  本次实际返回没有 Sidebar finding；上下文中提到的强制 Sidebar 同样缺少仓库依据，但不能捏造为本次工具输出。
B2. class/dynamic：DesktopWorkspace.tsx:26、:164 均不适用。
  工具声称动态 class 会让 Tailwind 不生成样式；项目未使用 Tailwind。完整 class 已由 CSS 显式定义：splitter、splitter--horizontal（CSS:48-50），review、review--open（CSS:69-70）。原生 CSS 不依赖 Tailwind 扫描生成。
B3. token/hardcoded-color 中的语义变量定义误判。
  index.css:2-11、DesktopWorkspace.css:2-16 正是在定义 --text/--surface/--accent/--pending/--danger/--normal 等语义 custom properties，消费者通过 var(...) 使用。工具“Replace it with a semantic custom property”在这些定义点属于循环要求；不能无限把 token 定义再换成另一 token 来凑零 finding。

C. 条件性建议 / 不能直接判为 serious 缺陷的规则
  token/px-length 对所有 px 一刀切的要求不符合当前仓库明确采用的 CSS 约定。
  边框、outline/outline-offset、圆角、阴影中的 px 本身不是无障碍失败证据；不能仅凭出现 px 判 serious。
  面板/拖拽尺寸、splitter 轨道、min-height、固定宽度、gap/padding/margin 应结合实际文本缩放、窄窗和 Electron 工作台行为验证，不能全部无条件豁免，也不能未经渲染就宣布溢出或缩放失败。拖动逻辑使用 clientX/clientY 像素，机械地只把 CSS 改为 rem 还可能造成尺寸体系不同步。
  除 A1 明确的字号适配项外，其余 px finding 保留为布局/字号缩放复核建议，而非本次已证明的 serious 运行时问题。
