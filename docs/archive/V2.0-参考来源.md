## 2. MDN IndexedDB

### 2.1 事务、错误与 abort 语义

- Using IndexedDB：https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Using_IndexedDB
  - 依据一：请求出错时默认会 abort 它所在的事务——原文 “the default behavior of
    an error is to abort the transaction in which it occurred”。
  - 依据二：未处理错误时整笔事务回滚——原文 “…the entire transaction is rolled back”。
  - 用途：`saveDraft` 把 drafts / importSnapshots / projects 的写入放进同一
    readwrite 事务；任一步失败整笔回滚。
- IDBDatabase.transaction(storeNames, mode)：https://developer.mozilla.org/en-US/docs/Web/API/IDBDatabase/transaction
  - 依据：`storeNames` 可传多个 store 名称的数组，使 projects、drafts、
    importSnapshots 处于同一事务。
- IDBTransaction.abort()：https://developer.mozilla.org/en-US/docs/Web/API/IDBTransaction/abort
  - 依据：显式取消事务；对已结束的事务再调用会抛 InvalidStateError，因此
    `saveDraft` 的 catch 忽略二次 abort 的异常。
- IDBRequest.error：https://developer.mozilla.org/en-US/docs/Web/API/IDBRequest/error
  - 依据：请求失败时从 `request.error` 取得 DOMException（B1 用例中的
    ConstraintError 即此来源）。
- IDBObjectStore.add：https://developer.mozilla.org/en-US/docs/Web/API/IDBObjectStore/add
  - 依据：`add` 在主键已存在时触发 ConstraintError，不覆盖已有记录；新快照必须
    用 add 而不是 put，否则会覆盖旧快照。
- IDBObjectStore.put：https://developer.mozilla.org/en-US/docs/Web/API/IDBObjectStore/put
  - 依据：`put` 按主键覆盖或新增，用于 projects / drafts 的保存。

### 2.2 索引与数据库版本

- IDBObjectStore.createIndex：https://developer.mozilla.org/en-US/docs/Web/API/IDBObjectStore/createIndex
  - 依据：importSnapshots 上建 `projectId` 索引（`db.ts` 的 onupgradeneeded）。
- IDBIndex.getAll：https://developer.mozilla.org/en-US/docs/Web/API/IDBIndex/getAll
  - 依据：`listImportSnapshots(projectId)` 通过 projectId 索引按项目取快照。
- IDBDatabase.createObjectStore：https://developer.mozilla.org/en-US/docs/Web/API/IDBDatabase/createObjectStore
  - 依据：数据库版本 1→2→3 升级时只创建缺失的 store / 索引，不重建、不清空
    已有数据（mappingTemplates、importSnapshots）。
- IDBObjectStore.add 的约束语义（同 2.1）：B1 用例把随机 UUID 固定后预置同主键
  快照，让生产 `add` 真的收到 ConstraintError 请求错误，而不是替换 `add` 打桩。

## 3. 测试环境

- fake-indexeddb（6.2.7，package.json）：https://github.com/dumbmatter/fakeIndexedDB
  - 依据：README 说明它是 “A pure JS in-memory implementation of the IndexedDB
    API”，主要用于在 Node.js 中测试依赖 IndexedDB 的代码；本项目通过
    `fake-indexeddb/auto` 在 jsdom 下运行。B1 用例依赖它真实的请求错误与事务
    abort 行为，失败不是 mock 出来的。
- Crypto.randomUUID：https://developer.mozilla.org/en-US/docs/Web/API/Crypto/randomUUID
  - 依据：生产代码用 `crypto.randomUUID()` 生成快照 ID；B1 用例仅固定这一个
    随机源来构造主键冲突，没有替换任何存储函数或 `IDBObjectStore.add`。
