## 1. 缺口与修复

修复前：复核区只显示活动条款，`RequirementStatusPanel` 的「定位任务书」只读取
`project.activeRequirementRevisionId`；`DesktopSourceView` 只把活动条款的
`source` 作为高亮绑定。旧版本 `RequirementRevision.source`（PDF revisionId / page /
rectPdf / pageBoxPdf）虽然已随项目文件保存，但界面上没有入口。

修复后：

1. 新增纯派生层 `src/requirements/history.ts`：
   - `resolveRequirementRevisionSource(snapshot, revisionId)` **按传入 revisionId**
     取该版本来源，返回 revisionId / page / rectPdf / pageBoxPdf / 可用性；
   - `listRequirementRevisionHistory(snapshot)` 列出项目全部条款版本（含旧版本），
     每条包含 revisionId、父版本、确认时间、上下限、来源 PDF 版本与文件名、页码、
     选区、是否活动；
   - 来源缺失时返回明确原因码与中文说明：`SOURCE_REVISION_MISSING` /
     `SOURCE_BLOB_MISSING` / `SOURCE_DECLARED_MISSING` / `SOURCE_HASH_MISMATCH` /
     `SOURCE_PAGE_OUT_OF_RANGE`。
2. 新增只读列表 `RequirementRevisionHistory`，同时出现在：
   - 复核区（「条款版本历史（只读）」，全宽表格）；
   - 「历史报告」页（同一组件，测试 id 前缀区分）。
3. `DesktopWorkspace` 点击任一版本只设置来源定位目标并切到「来源 PDF」页：
   - 打开该版本自己的 `source.revisionId` 与 `source.page`；
   - `PdfViewer` 的条款高亮绑定使用该版本保存的 `rectPdf`，不再使用活动版本；
   - 不调用任何 IPC 写入，不改活动条款指针。
4. 来源缺失时：来源页显示 `[data-testid="requirement-locate-error"]`，明确写出
   条款版本与来源 revisionId 及缺失原因，**不渲染 `.pdf-viewer`**，不会回退到
   第一个版本或活动版本。来源版本下拉框会把缺失 revisionId 显示为
   `sr-…（不在项目文件中）`，不会静默选中其它版本。
5. 未新增 IPC/契约；`src/pages/DesktopWorkspace.test.tsx` 的既有 `CunlianApi`
   假 mock 无需扩展。

未改：`src/domain` 公式与 q 精度、schema 7 判据、数值断言
（1500/2500、1100/2100、500/1500、1000/2000）、A/B1/B2/C/D 判据。

## 5. 变异实验（MUT-B35-5）

- 变异：`resolveRequirementRevisionSource` 中把
  `item.revisionId === revisionId` 改为
  `item.revisionId === snapshot.project.activeRequirementRevisionId`，
  即“永远取活动版本”。
- patch：`mutations/MUT-B35-5.patch`
- 红：`mutations/MUT-B35-5.red.log`，`EXIT_CODE:1`，失败用例正是
  「两个版本的 pdfRevisionId/页码/rect 不同时，定位结果分别取各自值」；
  实际收到活动版本 `reqrev-2 / sr-taskbook-2 / 第 1 页 / [20,40,220,80]`，
  期望旧版本 `reqrev-1 / sr-1 / 第 2 页 / [10,10,110,30]`。
- 恢复绿：`mutations/MUT-B35-5.green.log`，`EXIT_CODE:0`，1 passed。
- 变异只改 `src/requirements/history.ts`，跑完恢复；最终工作树无该改动。
