## 2. 版本对应 API（本地类型定义核对）

查阅位置：`node_modules/pdfjs-dist/types/src/display/page_viewport.d.ts` 第 124–136 行。

该版本的 `PageViewport` 只有：

- `convertToViewportPoint(x, y): any[]`
- `convertToPdfPoint(x, y): any[]`

**没有 `convertToViewportRectangle`**。任务卡所述“v6.1.200 起移除（mozilla/pdf.js PR #21426）”与本地安装包一致；本次没有依赖该已移除 API，而是：

1. 交互时把两个对角点分别用 `convertToPdfPoint` 变成 PDF 点；
2. 保存两个对角点，显示时重新 `page.getViewport({ scale, rotation })`，各自 `convertToViewportPoint`；
3. 用 `Math.min/Math.max` 合成 `minX/minY/maxX/maxY`。旋转 90/270 度时两点的屏幕顺序会改变（测试中 270 度已实测两个分量都反向），不能直接相减。

实测（真实 pdfjs-dist 6.5.438，合成 PDF 600×800）：

| rotation | scale | viewport 尺寸 | 说明 |
|---|---|---|---|
| 0 | 1 | 600×800 | 常规 |
| 90 | 1 | 800×600 | 宽高交换，两角顺序仍递增 |
| 180 | 1 | 600×800 | x 方向反向 |
| 270 | 1 | 800×600 | x、y 两个分量都反向，必须 min/max |

坐标往返误差与矩形两角颠倒测试见 `src/sources/pdfCoordinates.test.ts`。

## 6. 第二组补充：渲染、框选与 DB v5

记录时间：2026-11-08（PST）。

- 渲染 API：`pdfjs-dist 6.5.438` 的 `PDFPageProxy.getViewport({ scale, rotation })`
  与 `render({ canvasContext, viewport, transform })`，见本地包
  `types/src/display/api.d.ts` 与 `display/canvas.d.ts`。canvas 内部像素乘
  `outputScale`（通常 `devicePixelRatio`），CSS 尺寸保持 viewport 逻辑像素；
  指针坐标必须用 `getBoundingClientRect()` 比例映射。
- 页面边界：使用 `PDFPageProxy.view` 四元组 `[x0,y0,x1,y1]`（MediaBox），
  允许非零/负原点；不再使用 `pdfjs` 旧接口的 `[width,height] + [0,0]`。
  本版 `PageViewport` 没有 `convertToViewportRectangle`，因此保存两个对角点并
  在显示时用 min/max 合成。
- IndexedDB v5：
  - 新增 `bindings`（`id`，index `projectId`/`termId`/`revisionId`）与
    `events`（`id`，index `projectId`/`createdAt`）；只增补缺失 store/index。
  - `versionchange`：本页连接收到后立即关闭并通过订阅通知 UI；`blocked`：本次
    打开明确失败，阻塞解除后升级仍会完成，迟到的成功连接必须关闭。
  - `VersionError`：库升到 v5 后指定 `version=4` 的打开器会抛错。部署回滚不能
    只回退前端，也不能删库降级；旧页面必须刷新/关闭。详见
    `docs/V2.1-第二组-数据库与来源UI.md` §1.3。
- 自动化：`src/storage/db.test.ts`（真实 v4→v5、v1→v5、Blob 字节、VersionError、
  versionchange/blocked）、`src/components/PdfPageSurface.test.tsx`（八组合几何）、
  `src/components/SourcePanel.test.tsx`（同名新版后刷新仍打开旧 revision）。
